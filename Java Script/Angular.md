# Complete Modern Angular Tutorial: Basic to Advanced

This tutorial will take you from your first Angular component to a full-stack application using Angular + TypeScript + Spring Boot + PostgreSQL.

We'll build a product-management application step by step, learning each concept before using it in the project. The examples use modern Angular's standalone components, signals, built-in template control flow, and functional providers rather than older AngularJS patterns.

## What you'll build

Angular frontend

TypeScript · Components · Signals · Forms · Routing

localhost:4200

HTTP requests and JSON

Spring Boot REST API

Controllers · Services · Validation · JPA

localhost:8080

PostgreSQL

Persistent product data

By the end, you'll understand how to display data, handle user actions, validate forms, call REST endpoints, manage application state, and organize a maintainable Angular application.

## 3. TypeScript fundamentals for Angular

Angular uses TypeScript, which adds static types to JavaScript.

### 3.1 Variables and types

```ts
let name: string = 'Laptop';
let price: number = 45000;
let available: boolean = true;

let tags: string[] = ['Electronics', 'Computer'];
```

The type after `:` describes which values the variable can hold.

TypeScript can also infer types:

```ts
let quantity = 5;
// TypeScript infers number
```

### 3.2 Interfaces

An interface describes the structure of an object.

Create `src/app/product.ts`:

```ts
export interface Product {
  id: number;
  name: string;
  price: number;
  description: string;
}
```

Use it in another file:

```ts
import { Product } from './product';

const product: Product = {
  id: 1,
  name: 'Laptop',
  price: 45000,
  description: 'A development laptop'
};
```

If you omit a required property or assign an incompatible type, TypeScript can report an error during development.

### 3.3 Classes

```ts
export class Calculator {
  add(a: number, b: number): number {
    return a + b;
  }
}

const calculator = new Calculator();
console.log(calculator.add(10, 20));
```

Classes are useful for understanding Angular's component classes, although you won't need to create a class for every piece of data.

### 3.4 Arrays and array methods

```ts
const prices = [100, 200, 300];

const increased = prices.map(price => price + 10);
const expensive = prices.filter(price => price >= 200);
const total = prices.reduce((sum, price) => sum + price, 0);
```

- `map()` transforms items.
    
- `filter()` selects items.
    
- `reduce()` combines items into one result.
    

These methods are particularly useful for frontend data processing.

### 3.5 Arrow functions

```ts
const multiply = (a: number, b: number): number => a * b;
```

The same idea appears in Angular signals:

```ts
count.update(value => value + 1);
```

### 3.6 Promises and asynchronous code

```ts
async function loadMessage(): Promise<string> {
  return 'Hello Angular';
}

loadMessage().then(message => console.log(message));
```

You'll encounter promises, but Angular's `HttpClient` commonly returns RxJS `Observable` objects instead. We'll cover those later.

## 4. Your first real Angular component

Let's build a counter from scratch.

Generate a component:

```
ng generate component counter
```

In the generated counter TypeScript file, use:

```
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-counter',
  standalone: true,
  template: `
    <h2>Counter: {{ count() }}</h2>

    <button (click)="increment()">+</button>
    <button (click)="decrement()">-</button>
    <button (click)="reset()">Reset</button>
  `
})
export class Counter {
  count = signal(0);

  increment(): void {
    this.count.update(value => value + 1);
  }

  decrement(): void {
    this.count.update(value => value - 1);
  }

  reset(): void {
    this.count.set(0);
  }
}
```

If your generated component already has `standalone: true`, keep it. In recent Angular versions, standalone is the default, so explicitly setting it is optional.

Now display it in your root component's template:

```
<app-counter />
```

And add the component to the root component's imports. For example, in `app.ts`:

```
import { Component } from '@angular/core';
import { Counter } from './counter/counter';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [Counter],
  templateUrl: './app.html',
  styleUrl: './app.css'
})
export class App {}
```

Adjust the import path to match the filenames generated in your project.

### What happens when you click `+`?

1. Event

Angular handles the button's click event.

2. Method

`increment()` updates the signal.

3. UI update

Angular refreshes the displayed counter value.

This is the basic pattern behind many interactive Angular applications.

## 5. Angular template syntax

A template is HTML enhanced with Angular expressions and bindings.

### 5.1 Interpolation

Use `{{ }}` to display a value.

```
export class App {
  productName = 'Mechanical Keyboard';
  price = 2500;
}
```

Template:

```
<h1>{{ productName }}</h1>
<p>Price: ₹{{ price }}</p>
<p>Total: ₹{{ price * 2 }}</p>
```

Interpolation is intended for displaying values in text.

### 5.2 Property binding

Use square brackets to bind a value to an element property.

```
export class App {
  imageUrl = 'https://example.com/product.jpg';
  isDisabled = true;
}
```

```
<img [src]="imageUrl" alt="Product">

<button [disabled]="isDisabled">
  Purchase
</button>
```

Angular evaluates the expression and assigns the result to the property.

### 5.3 Event binding

Use parentheses to respond to events.

```
export class App {
  message = 'Waiting';

  greet(): void {
    this.message = 'Hello!';
  }
}
```

```
<button (click)="greet()">Click me</button>
<p>{{ message }}</p>
```

### 5.4 Two-way binding

Two-way binding synchronizes a form control and a component property.

For this example, import `FormsModule` into the component:

```
import { Component } from '@angular/core';
import { FormsModule } from '@angular/forms';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [FormsModule],
  template: `
    <input [(ngModel)]="username">
    <p>Hello, {{ username }}</p>
  `
})
export class App {
  username = '';
}
```

The expression `[(ngModel)]` combines property binding and event binding. It is useful for simple forms and interactive inputs.

### 5.5 Conditions with `@if`

```
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-root',
  template: `
    <button (click)="toggle()">Toggle</button>

    @if (loggedIn()) {
      <p>Welcome back!</p>
    } @else {
      <p>Please log in.</p>
    }
  `
})
export class App {
  loggedIn = signal(false);

  toggle(): void {
    this.loggedIn.update(value => !value);
  }
}
```

### 5.6 Loops with `@for`

```
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-root',
  template: `
    @for (product of products(); track product.id) {
      <p>{{ product.name }} — ₹{{ product.price }}</p>
    } @empty {
      <p>No products found.</p>
    }
  `
})
export class App {
  products = signal([
    { id: 1, name: 'Mouse', price: 500 },
    { id: 2, name: 'Keyboard', price: 1500 },
    { id: 3, name: 'Monitor', price: 9000 }
  ]);
}
```

`track product.id` gives Angular a stable identifier for each product. Use a unique ID where possible.

### 5.7 Class and style binding

```
<p [class.active]="isActive">
  Status
</p>

<p [style.color]="isActive ? 'green' : 'red'">
  {{ isActive ? 'Active' : 'Inactive' }}
</p>
```

For modern Angular templates, the key syntax to remember is:

|Syntax|Purpose|
|---|---|
|`{{ value }}`|Display a value|
|`[property]="value"`|Bind a property|
|`(event)="method()"`|Handle an event|
|`[(ngModel)]="value"`|Two-way form binding|
|`@if`|Conditional rendering|
|`@for`|Repeated rendering|
|`@switch`|Multiple conditional cases|

## 6. Signals and computed state

Signals are central to modern Angular state management.

### 6.1 `signal()`

A writable signal stores a value.

```
import { signal } from '@angular/core';

count = signal(0);
```

Read it:

```
console.log(this.count());
```

Replace the value:

```
this.count.set(10);
```

Update based on the current value:

```
this.count.update(value => value + 1);
```

Notice that you call a signal as a function to read it.

### 6.2 `computed()`

A computed signal derives a value from other signals.

```
import { Component, signal, computed } from '@angular/core';

@Component({
  selector: 'app-root',
  template: `
    <p>Price: ₹{{ price() }}</p>
    <p>Quantity: {{ quantity() }}</p>
    <h3>Total: ₹{{ total() }}</h3>

    <button (click)="quantity.update(q => q + 1)">
      Add one
    </button>
  `
})
export class App {
  price = signal(500);
  quantity = signal(1);

  total = computed(() => this.price() * this.quantity());
}
```

When either `price` or `quantity` changes, Angular recalculates `total` when needed.

### 6.3 Updating objects and arrays

Don't mutate a signal's array and expect the signal to detect the mutation automatically.

Avoid:

```
this.products().push(newProduct);
```

Prefer:

```
this.products.update(items => [...items, newProduct]);
```

For updating one product:

```
this.products.update(items =>
  items.map(product =>
    product.id === updatedProduct.id
      ? updatedProduct
      : product
  )
);
```

For removing one:

```
this.products.update(items =>
  items.filter(product => product.id !== productId)
);
```

### 6.4 `effect()`

Effects are for synchronizing signal-driven state with something external, such as browser logging or a third-party library.

```
import { effect, signal } from '@angular/core';

count = signal(0);

constructor() {
  effect(() => {
    console.log('Current count:', this.count());
  });
}
```

Angular manages the effect's reactive dependencies. Avoid using effects just to calculate values that could be expressed with `computed()`.

### 6.5 When to use signals and RxJS

- Use signals for UI state, selected items, filters, and derived values.
    
- Use RxJS for asynchronous streams, HTTP pipelines, cancellation, timing, and combining events.
    
- Use both when appropriate; they solve related but different problems.
    

## 7. Component communication

Real applications have many components. For example, a parent product page might contain a product card.

### 7.1 Pass data using `input()`

Create `product-card.ts`:

```
import { Component, input } from '@angular/core';
import { Product } from '../product';

@Component({
  selector: 'app-product-card',
  standalone: true,
  template: `
    <h3>{{ product().name }}</h3>
    <p>₹{{ product().price }}</p>
  `
})
export class ProductCard {
  product = input.required<Product>();
}
```

Use it in a parent template:

```
<app-product-card [product]="selectedProduct" />
```

The parent passes data through a property binding, and the child reads the input signal using `product()`.

### 7.2 Send events using `output()`

Modify the card:

```
import { Component, input, output } from '@angular/core';
import { Product } from '../product';

@Component({
  selector: 'app-product-card',
  standalone: true,
  template: `
    <h3>{{ product().name }}</h3>
    <p>₹{{ product().price }}</p>

    <button (click)="remove.emit(product().id)">
      Remove
    </button>
  `
})
export class ProductCard {
  product = input.required<Product>();
  remove = output<number>();
}
```

The parent listens for the event:

```
<app-product-card
  [product]="selectedProduct"
  (remove)="removeProduct($event)"
/>
```

```
removeProduct(id: number): void {
  // Handle removal in the parent.
}
```

This is the typical direction of communication: inputs pass data down, and outputs notify the parent about events.

## 8. Services and dependency injection

A service holds reusable logic or data access code. Components should generally focus on the UI rather than directly implementing every operation.

Generate a service:

```
ng generate service services/product
```

A simple local-data service:

```
import { Injectable, signal } from '@angular/core';
import { Product } from '../product';

@Injectable({
  providedIn: 'root'
})
export class ProductService {
  private products = signal<Product[]>([
    {
      id: 1,
      name: 'Keyboard',
      price: 1500,
      description: 'Mechanical keyboard'
    },
    {
      id: 2,
      name: 'Mouse',
      price: 500,
      description: 'Wireless mouse'
    }
  ]);

  getProducts() {
    return this.products;
  }
}
```

Inject it into a component:

```
import { Component, inject } from '@angular/core';
import { ProductService } from './services/product';

@Component({
  selector: 'app-root',
  template: `
    @for (product of products(); track product.id) {
      <p>{{ product.name }} — ₹{{ product.price }}</p>
    }
  `
})
export class App {
  private productService = inject(ProductService);
  products = this.productService.getProducts();
}
```

`providedIn: 'root'` makes the service available through the application's root injector, usually as a shared singleton instance.

This pattern is important for our REST API integration: the service will become responsible for calling Spring Boot, and components will consume the service's methods.

Generate the components:

```
ng generate component pages/product-list
ng generate component pages/product-form

### 9.1 Define routes

Edit `src/app/app.routes.ts`:

```
import { Routes } from '@angular/router';
import { ProductList } from './pages/product-list/product-list';
import { ProductForm } from './pages/product-form/product-form';
import { ProductDetail } from './pages/product-detail/product-detail';

export const routes: Routes = [
  { path: '', redirectTo: 'products', pathMatch: 'full' },
  { path: 'products', component: ProductList },
  { path: 'products/new', component: ProductForm },
  { path: 'products/:id', component: ProductDetail },
  { path: '**', redirectTo: 'products' }
];
```

The imports must match your generated filenames.

Important: Put `products/new` before `products/:id`. Otherwise, the router may interpret `new` as an ID.

### 9.2 Configure the router

Edit `src/app/app.config.ts`:

```
import { ApplicationConfig } from '@angular/core';
import { provideRouter } from '@angular/router';
import { provideHttpClient } from '@angular/common/http';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideHttpClient()
  ]
};
```

If your CLI has already configured `provideRouter`, retain it and add only the missing provider.

### 9.3 Add navigation

In `app.html`:

```
<nav>
  <a routerLink="/products">Products</a>
  |
  <a routerLink="/products/new">Add product</a>
</nav>

<router-outlet />
```

Import the router directives into the root component:

```
import { RouterLink, RouterOutlet } from '@angular/router';
```

Then add `RouterLink` and `RouterOutlet` to the component's `imports` array.

### 10.1 Create a reactive form

In `product-form.ts`:

```
import { Component, inject } from '@angular/core';
import {
  FormBuilder,
  ReactiveFormsModule,
  Validators
} from '@angular/forms';

@Component({
  selector: 'app-product-form',
  standalone: true,
  imports: [ReactiveFormsModule],
  template: `
    <h2>Add product</h2>

    <form [formGroup]="form" (ngSubmit)="submit()">
      <label>
        Name
        <input formControlName="name">
      </label>

      @if (form.controls.name.touched &&
           form.controls.name.invalid) {
        <p>Name is required.</p>
      }

      <label>
        Price
        <input type="number" formControlName="price">
      </label>

      @if (form.controls.price.touched &&
           form.controls.price.invalid) {
        <p>Enter a valid positive price.</p>
      }

      <label>
        Description
        <textarea formControlName="description"></textarea>
      </label>

      <button type="submit" [disabled]="form.invalid">
        Save
      </button>
    </form>
  `
})
export class ProductForm {
  private fb = inject(FormBuilder);

  form = this.fb.nonNullable.group({
    name: ['', Validators.required],
    price: [0, [Validators.required, Validators.min(0.01)]],
    description: ['']
  });

  submit(): void {
    if (this.form.invalid) {
      return;
    }

    console.log(this.form.getRawValue());
  }
}
```

### 10.2 Understand the form

|Feature|Purpose|
|---|---|
|`FormBuilder`|Creates form controls conveniently|
|`formGroup`|Connects the form model to the HTML form|
|`formControlName`|Connects an input to a form control|
|`Validators.required`|Requires a value|
|`Validators.min(0.01)`|Requires a price of at least 0.01|
|`form.invalid`|Checks whether the form has validation errors|
|`getRawValue()`|Returns the form's current values|

This version only logs the submitted data. We'll replace that line with a Spring Boot API call later.

Remember: frontend validation improves usability, but the backend must validate incoming data too.

# Part 2 — Integrate Angular with Spring Boot

## 11. Understand the HTTP request lifecycle

Angular does not directly access PostgreSQL. It sends HTTP requests to Spring Boot, which performs the required operations.

1. Angular component

User clicks Save

2. Angular service

HttpClient sends POST request

3. Spring Boot controller

Receives JSON and validates input

4. Service, repository and PostgreSQL

Processes and saves the product

Spring Boot returns JSON; Angular updates the UI.

Angular's `HttpClient` supports GET, POST, PUT, PATCH and DELETE. Its methods return RxJS observables, and a request is sent when the observable is subscribed to.

### 12.1 Configure PostgreSQL

```

```

In `src/main/resources/application.properties`:

```
spring.datasource.url=jdbc:postgresql://localhost:5432/productdb

### 12.2 Create the entity

`Product.java`:

```
package com.example.productapi;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.validation.constraints.DecimalMin;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Size;

import java.math.BigDecimal;

@Entity
public class Product {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @NotBlank
    @Size(max = 120)
    private String name;

    @NotNull
    @DecimalMin("0.01")
    private BigDecimal price;

    @Size(max = 1000)
    private String description;

    public Product() {}

    public Long getId() {
        return id;
    }

    public String getName() {
        return name;
    }

    public BigDecimal getPrice() {
        return price;
    }

    public String getDescription() {
        return description;
    }

    public void setId(Long id) {
        this.id = id;
    }

    public void setName(String name) {
        this.name = name;
    }

    public void setPrice(BigDecimal price) {
        this.price = price;
    }

    public void setDescription(String description) {
        this.description = description;
    }
}
```

Here, `@Entity` maps the Java class to a database entity. JPA uses the ID to identify each product.

### 12.3 Create the repository

`ProductRepository.java`:

```

import org.springframework.data.jpa.repository.JpaRepository;

public interface ProductRepository
        extends JpaRepository<Product, Long> {
}
```

Spring Data JPA provides common CRUD methods through `JpaRepository`, so you don't need to write SQL for every basic operation.

### 12.4 Create the service

`ProductService.java`:

```
package com.example.productapi;

import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Service;
import org.springframework.web.server.ResponseStatusException;

import java.util.List;

@Service
public class ProductService {

    private final ProductRepository repository;

    public ProductService(ProductRepository repository) {
        this.repository = repository;
    }

    public List<Product> findAll() {
        return repository.findAll();
    }

    public Product findById(Long id) {
        return repository.findById(id)
                .orElseThrow(() -> new ResponseStatusException(
                        HttpStatus.NOT_FOUND, "Product not found"));
    }

    public Product create(Product product) {
        product.setId(null);
        return repository.save(product);
    }

    public Product update(Long id, Product input) {
        Product existing = findById(id);

        existing.setName(input.getName());
        existing.setPrice(input.getPrice());
        existing.setDescription(input.getDescription());

        return repository.save(existing);
    }

    public void delete(Long id) {
        Product existing = findById(id);
        repository.delete(existing);
    }
}
```

The service layer keeps application logic separate from the HTTP layer.

### 12.5 Create the REST controller

`ProductController.java`:

```
package com.example.productapi;

import jakarta.validation.Valid;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/api/products")
public class ProductController {

    private final ProductService service;

    public ProductController(ProductService service) {
        this.service = service;
    }

    @GetMapping
    public List<Product> findAll() {
        return service.findAll();
    }

    @GetMapping("/{id}")
    public Product findById(@PathVariable Long id) {
        return service.findById(id);
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public Product create(@Valid @RequestBody Product product) {
        return service.create(product);
    }

    @PutMapping("/{id}")
    public Product update(
            @PathVariable Long id,
            @Valid @RequestBody Product product) {
        return service.update(id, product);
    }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    public void delete(@PathVariable Long id) {
        service.delete(id);
    }
}
```

`@RequestBody` converts incoming JSON to a Java object. `@Valid` applies the Bean Validation constraints. `@PathVariable` extracts the ID from the URL.

### 12.6 Enable CORS for local development

Angular and Spring Boot run on different ports, so the browser treats them as different origins.

Create `CorsConfig.java`:

```
package com.example.productapi;

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class CorsConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/api/**")
                .allowedOrigins("http://localhost:4200")
                .allowedMethods(
                        "GET", "POST", "PUT", "PATCH", "DELETE"
                )
                .allowedHeaders("*");
    }
}
```

This permits the local Angular development origin to access your API. Restrict allowed origins and headers appropriately for production. If you later add Spring Security, ensure its CORS configuration is compatible too.

## 13. Call Spring Boot from Angular using `HttpClient`

Now that the backend is running, let's connect Angular to it.

### 13.1 Configure `HttpClient`

In `app.config.ts`, make sure you have:

```
import { provideHttpClient } from '@angular/common/http';
```

And:

```
providers: [
  provideRouter(routes),
  provideHttpClient()
]
```

Do not register `provideHttpClient()` repeatedly in every component. Configure it once at the application level unless you have a specific reason to configure a separate injector.

### 13.2 Create the TypeScript model

Use `src/app/product.ts`:

```
export interface Product {
  id: number;
  name: string;
  price: number;
  description: string;
}

export type CreateProduct = Omit<Product, 'id'>;
```

`Omit<Product, 'id'>` creates a type with all the product fields except `id`. This is useful because the server generates the ID when creating a product.

### 13.3 Create the API service

Create or replace `src/app/services/product.ts`:

```
import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';
import { Product, CreateProduct } from '../product';

@Injectable({
  providedIn: 'root'
})
export class ProductService {
  private http = inject(HttpClient);

  private apiUrl = 'http://localhost:8080/api/products';

  getAll(): Observable<Product[]> {
    return this.http.get<Product[]>(this.apiUrl);
  }

  getById(id: number): Observable<Product> {
    return this.http.get<Product>(`${this.apiUrl}/${id}`);
  }

  create(product: CreateProduct): Observable<Product> {
    return this.http.post<Product>(this.apiUrl, product);
  }

  update(id: number, product: CreateProduct): Observable<Product> {
    return this.http.put<Product>(
      `${this.apiUrl}/${id}`,
      product
    );
  }

  delete(id: number): Observable<void> {
    return this.http.delete<void>(`${this.apiUrl}/${id}`);
  }
}
```

### Understand this service

- `HttpClient` sends HTTP requests.
    
- `Observable<Product[]>` represents an asynchronous stream of product data.
    
- `getAll()` sends a GET request.
    
- `create()` sends a POST request with JSON.
    
- `update()` sends a PUT request.
    
- `delete()` sends a DELETE request.
    

The generic types help TypeScript understand the expected response shape, but they don't validate incoming JSON at runtime. Ensure your backend returns the expected data.

### 13.4 Display products from the API

Edit the generated `product-list.ts`:

```
import { Component, inject, signal } from '@angular/core';
import { RouterLink } from '@angular/router';
import { ProductService } from '../../services/product';
import { Product } from '../../product';

@Component({
  selector: 'app-product-list',
  standalone: true,
  imports: [RouterLink],
  template: `
    <h1>Products</h1>

    <a routerLink="/products/new">Add product</a>

    @if (loading()) {
      <p>Loading products...</p>
    } @else if (error()) {
      <p>{{ error() }}</p>
      <button (click)="loadProducts()">Retry</button>
    } @else {
      @for (product of products(); track product.id) {
        <article>
          <h3>{{ product.name }}</h3>
          <p>₹{{ product.price }}</p>
          <p>{{ product.description }}</p>

          <a [routerLink]="['/products', product.id]">
            View details
          </a>

          <button (click)="deleteProduct(product.id)">
            Delete
          </button>
        </article>
      } @empty {
        <p>No products found.</p>
      }
    }
  `
})
export class ProductList {
  private service = inject(ProductService);

  products = signal<Product[]>([]);
  loading = signal(false);
  error = signal('');

  constructor() {
    this.loadProducts();
  }

  loadProducts(): void {
    this.loading.set(true);
    this.error.set('');

    this.service.getAll().subscribe({
      next: products => {
        this.products.set(products);
        this.loading.set(false);
      },
      error: err => {
        console.error(err);
        this.error.set('Could not load products.');
        this.loading.set(false);
      }
    });
  }

  deleteProduct(id: number): void {
    if (!confirm('Delete this product?')) {
      return;
    }

    this.service.delete(id).subscribe({
      next: () => this.loadProducts(),
      error: err => {
        console.error(err);
        this.error.set('Could not delete product.');
      }
    });
  }
}
```

This component uses the service rather than accessing `HttpClient` directly. It also provides loading, error, empty-list and retry states.

Why does `subscribe()` matter?

`HttpClient` observables are lazy: subscribing initiates the request. The `next` callback processes a successful response, and the `error` callback handles failure. An HTTP request observable normally completes after the response.

### 13.6 Build the product details page

In `product-detail.ts`:

```
import { Component, inject, signal } from '@angular/core';
import { ActivatedRoute, RouterLink } from '@angular/router';
import { ProductService } from '../../services/product';
import { Product } from '../../product';

@Component({
  selector: 'app-product-detail',
  standalone: true,
  imports: [RouterLink],
  template: `
    <a routerLink="/products">Back to products</a>

    @if (loading()) {
      <p>Loading...</p>
    } @else if (product(); as p) {
      <h1>{{ p.name }}</h1>
      <p>Price: ₹{{ p.price }}</p>
      <p>{{ p.description }}</p>
    } @else {
      <p>{{ error() }}</p>
    }
  `
})
export class ProductDetail {
  private route = inject(ActivatedRoute);
  private service = inject(ProductService);

  product = signal<Product | null>(null);
  loading = signal(true);
  error = signal('');

  constructor() {
    const id = Number(this.route.snapshot.paramMap.get('id'));

    if (!Number.isInteger(id) || id <= 0) {
      this.error.set('Invalid product ID.');
      this.loading.set(false);
      return;
    }

    this.service.getById(id).subscribe({
      next: product => {
        this.product.set(product);
        this.loading.set(false);
      },
      error: () => {
        this.error.set('Product not found or could not be loaded.');
        this.loading.set(false);
      }
    });
  }
}
```

For this simple page, reading the route snapshot is sufficient. For a component that stays mounted while route parameters change, use `ActivatedRoute.paramMap` as an observable or another reactive approach so the displayed product updates.

## 14. RxJS: the essential advanced concepts

Angular's HTTP API is based on RxJS observables. RxJS is useful when you need to transform, combine, filter or cancel asynchronous work.

### 14.1 Observable vs Promise

A Promise represents a single eventual result. An Observable can represent a stream of zero, one or many values over time.

```
import { Observable } from 'rxjs';

const numbers = new Observable<number>(subscriber => {
  subscriber.next(10);
  subscriber.next(20);
  subscriber.next(30);
  subscriber.complete();
});

numbers.subscribe(value => console.log(value));
```

Output:

```
10
20
30
```

This example emits synchronously. Real HTTP requests are asynchronous.

### 14.2 Transform results with `map`

```
import { map } from 'rxjs';

this.service.getAll()
  .pipe(
    map(products => products.filter(p => p.price >= 1000))
  )
  .subscribe(products => {
    console.log(products);
  });
```

This filters products in the frontend after receiving them. For large datasets, prefer backend filtering and pagination.

### 14.3 Search with `debounceTime` and `switchMap`

A search box can send too many requests if you query on every keystroke. Debouncing waits for the user to pause typing.

```
import { Component, inject, signal } from '@angular/core';
import { FormControl, ReactiveFormsModule } from '@angular/forms';
import { debounceTime, distinctUntilChanged, switchMap } from 'rxjs';

@Component({
  selector: 'app-search',
  standalone: true,
  imports: [ReactiveFormsModule],
  template: `
    <input [formControl]="query" placeholder="Search products">

    @for (name of results(); track name) {
      <p>{{ name }}</p>
    }
  `
})
export class Search {
  query = new FormControl('', { nonNullable: true });
  results = signal<string[]>([]);

  constructor() {
    this.query.valueChanges.pipe(
      debounceTime(300),
      distinctUntilChanged(),
      switchMap(query =>
        // Replace with an actual API search method.
        import('rxjs').then(() => query)
      )
    ).subscribe(query => {
      this.results.set(query ? [query] : []);
    });
  }
}
```

This is a basic illustration of the operator sequence, but dynamic import is unnecessary for a real search. Here is the cleaner approach for local search results:

```
import { map, debounceTime, distinctUntilChanged } from 'rxjs';

constructor() {
  this.query.valueChanges.pipe(
    debounceTime(300),
    distinctUntilChanged(),
    map(query => query.toLowerCase())
  ).subscribe(query => {
    this.results.set(
      ['Keyboard', 'Mouse', 'Monitor']
        .filter(name => name.toLowerCase().includes(query))
    );
  });
}
```

For a real backend search, replace the `map()` pipeline with `switchMap(query => this.service.search(query))`. `switchMap` unsubscribes from the previous inner observable when a new query arrives, which is especially useful for search requests.

### 14.3 Handle errors with `catchError`

```
import { catchError, of } from 'rxjs';

this.service.getAll().pipe(
  catchError(error => {
    console.error(error);
    return of([]);
  })
).subscribe(products => {
  this.products.set(products);
});
```

Returning an empty list is appropriate only if the UI can distinguish an empty result from a failed request. For production applications, keep error and data states separate when that distinction matters.

### 14.4 Avoid unnecessary subscriptions

For simple template-driven display, the `async` pipe subscribes to an observable and handles its subscription lifecycle.

For example:

```
products$ = this.service.getAll();
```

Template:

```
@if (products$ | async; as products) {
  @for (product of products; track product.id) {
    <p>{{ product.name }}</p>
  }
}
```

Import `AsyncPipe` from `@angular/common` into the component's `imports`.

For more advanced cases, Angular also supports `toSignal()` to consume an observable as signal-based state. Choose a single clear state-management approach for each data flow rather than mixing many patterns without a reason.

## 15. HTTP interceptors

An interceptor can add headers, log requests, or handle common errors centrally. This is useful when you later integrate Spring Security.

Generate an interceptor:

```
ng generate interceptor interceptors/api
```

Example functional interceptor:

```
import { HttpInterceptorFn } from '@angular/common/http';

export const apiInterceptor: HttpInterceptorFn = (req, next) => {
  const started = Date.now();

  return next(req).pipe();
};
```

A simple logging interceptor can use `finalize`:

```
import { HttpInterceptorFn } from '@angular/common/http';
import { finalize } from 'rxjs';

export const loggingInterceptor: HttpInterceptorFn = (req, next) => {
  const started = Date.now();

  return next(req).pipe(
    finalize(() => {
      console.log(
        req.method,
        req.url,
        `${Date.now() - started}ms`
      );
    })
  );
};
```

Register it in `app.config.ts`:

```
import {
  provideHttpClient,
  withInterceptors
} from '@angular/common/http';

providers: [
  provideRouter(routes),
  provideHttpClient(
    withInterceptors([loggingInterceptor])
  )
]
```

This is an example of a functional interceptor, the modern approach to shared HTTP request behavior.

### Add an authentication token

After you implement login, a token interceptor can attach a bearer token to API requests.

```
import { HttpInterceptorFn } from '@angular/common/http';

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = sessionStorage.getItem('access_token');

  if (!token || !req.url.startsWith('http://localhost:8080/api/')) {
    return next(req);
  }

  return next(req.clone({
    setHeaders: {
      Authorization: `Bearer ${token}`
    }
  }));
};
```

Register it in `withInterceptors()` along with any other interceptors you use.

This example is for learning, not a complete security design. Browser storage can be exposed by successful cross-site scripting attacks. For a production application, carefully evaluate the authentication flow, token storage, CSRF protections, HTTPS, refresh-token handling, and your Spring Security configuration. Never assume the frontend alone can authorize an operation.

## 16. Route guards

A route guard controls whether Angular permits navigation to a route. It is useful for redirecting users who aren't logged in.

Create a guard:

```
ng generate guard guards/auth
```

Example functional guard:

```
import { CanActivateFn, Router } from '@angular/router';
import { inject } from '@angular/core';

export const authGuard: CanActivateFn = () => {
  const router = inject(Router);
  const token = sessionStorage.getItem('access_token');

  return token ? true : router.parseUrl('/login');
};
```

Add it to a route:

```
{
  path: 'admin',
  component: AdminPage,
  canActivate: [authGuard]
}
```

You must implement the login page and authentication flow separately.

Security rule: A route guard only controls navigation in the frontend. A user can bypass it by calling the REST API directly. Spring Security must independently enforce authorization on the server.

## 17. Lazy loading

Lazy loading lets Angular load certain features only when needed. This can reduce the amount of JavaScript required for the initial application load.

A standalone component can be loaded through a route:

```
import { Routes } from '@angular/router';

export const routes: Routes = [
  {
    path: 'reports',
    loadComponent: () =>
      import('./pages/reports/reports')
        .then(m => m.Reports)
  }
];
```

This example assumes `Reports` is a standalone component exported from the specified file.

For a larger feature with multiple routes, use `loadChildren` to lazy-load the route configuration.

Use lazy loading for substantial features such as reporting, administration, analytics or account settings. You usually don't need to lazy-load every tiny component.

## 18. Lifecycle hooks

Angular components have a lifecycle. Some hooks let you react to component initialization, changes and destruction.

Common hooks:

|Hook|Purpose|
|---|---|
|`ngOnInit`|Runs during initialization after inputs are initialized|
|`ngOnChanges`|Responds to changes in inputs|
|`ngAfterViewInit`|Runs after the component view is initialized|
|`ngOnDestroy`|Runs before the component is destroyed|

Example:

```
import { Component, OnInit } from '@angular/core';

@Component({
  selector: 'app-example',
  template: '<p>Check the browser console.</p>'
})
export class Example implements OnInit {
  ngOnInit(): void {
    console.log('Component initialized');
  }
}
```

For one-time initialization, a constructor or field initializer may be enough, depending on what you're doing. Use `ngOnInit` when initialization depends on Angular's component lifecycle.

For manual subscriptions to long-lived observables, make sure they are cleaned up when appropriate. `HttpClient` observables normally complete after the response, whereas event streams can remain active for the lifetime of the application.

## 19. Advanced state management

You can start with signals and services. You don't need NgRx or another state-management library for every application.

For example, shared cart state can live in a root-provided service:

```
import { Injectable, computed, signal } from '@angular/core';
import { Product } from '../product';

@Injectable({ providedIn: 'root' })
export class CartService {
  private items = signal<Product[]>([]);

  cartItems = this.items.asReadonly();

  itemCount = computed(() => this.items().length);

  total = computed(() =>
    this.items().reduce(
      (sum, product) => sum + product.price,
      0
    )
  );

  add(product: Product): void {
    this.items.update(items => [...items, product]);
  }

  clear(): void {
    this.items.set([]);
  }
}
```

The example treats each array entry as one cart item. A real cart normally stores a product ID and quantity, and calculates the total using `price * quantity`.

The service provides shared state without requiring components to pass data through every intermediate parent.

When an application becomes much more complex, consider additional patterns or libraries if you need explicit action flows, state persistence, debugging tools, or more structured side-effect management.

## 21. Production build and performance

When the application is ready to deploy, create a production build:

```

```

### Performance best practices

1. Use `@for` with stable tracking keys.
    
2. Use computed signals for derived state.
    
3. Lazy-load large features.
    
4. Avoid unnecessary subscriptions and duplicate HTTP requests.
    
5. Use pagination for large product lists.
    
6. Keep components focused and move reusable logic into services.
    
7. Use `OnPush` change detection when appropriate, especially in larger applications.
    
8. Use Angular's built-in sanitization correctly; don't bypass it for untrusted content.
    
9. Test production builds instead of relying only on `ng serve`.
    
10. Keep API secrets on the backend. Frontend environment configuration is visible to users.
    

### Deployment architecture

For production, you could serve Angular's static files through a web server such as Nginx, while Spring Boot runs separately behind an API URL such as `/api`.

```
Browser
   |
   v
Nginx
   |-- Angular static files
   |
   |-- /api/* --> Spring Boot
                       |
                       v
                   PostgreSQL
```

Serving both frontend and API under the same public origin can simplify CORS configuration. Configure SPA fallback routing so that direct navigation to `/products/123` serves the Angular entry point.

## 22. Common problems and fixes

|Problem|What to check|
|---|---|
|`ng: command not found`|Node.js/npm installation and Angular CLI availability|
|`Cannot find module`|Import path and generated filename|
|Unknown element or directive|Import the component, directive or pipe into the standalone component|
|`No provider for HttpClient`|Configure `provideHttpClient()`|
|API request blocked by CORS|Check Spring Boot CORS settings and the actual frontend origin|
|`Connection refused`|Confirm Spring Boot is running on port 8080|
|HTTP 400|Inspect JSON structure and backend validation errors|
|HTTP 404|Check the URL, route, product ID and controller mappings|
|HTTP 401/403|Check authentication and authorization configuration|
|Form never submits|Inspect validators and the form's `invalid` state|
|UI doesn't update as expected|Check signal reads/writes and whether the template is consuming the state correctly|

When debugging API requests, open the browser's developer tools and inspect the Network tab. You can see the request URL, method, status, request payload and response.
